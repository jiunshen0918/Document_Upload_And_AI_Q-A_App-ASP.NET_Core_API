# linux_mobile_app

Flutter client for the ASP.NET API.

## Use this project from Windows and Ubuntu

Keep a separate checkout on each operating system and use Git to share source
changes. Do not open the same project directory from Windows and Ubuntu (for
example, through a shared drive or mounted Windows folder). Flutter writes
machine-specific SDK paths and build outputs into `.dart_tool/` and `build/`;
those files are local to a checkout and must be generated by that machine's
Flutter SDK.

### One-time setup

Create a Git repository for this project and push it to a remote repository
that both machines can access. This project already ignores `.dart_tool/`,
`build/`, and Flutter plugin metadata, so those generated files will not be
committed. Keep `pubspec.yaml` and `pubspec.lock` in Git; they describe the
dependencies each machine should resolve.

### Windows

Clone the remote into a Windows-local folder, then open that clone:

```powershell
git clone <repository-url> C:\dev\linux_mobile_app
cd C:\dev\linux_mobile_app
flutter pub get
```

### Ubuntu

Clone the same remote into a Linux-local folder (not a Windows-mounted folder),
then open that clone:

```bash
git clone <repository-url> ~/dev/linux_mobile_app
cd ~/dev/linux_mobile_app
flutter pub get
```

### Share source changes

On the machine where you made changes, commit and push them. On the other
machine, pull the changes and run `flutter pub get` if `pubspec.yaml` or
`pubspec.lock` changed. Each checkout then has its own `.dart_tool/` and
`build/`, generated with that operating system's Flutter SDK.

If this project was opened in a shared folder before, stop using that folder
for Flutter runs. Clone the repository separately on each OS, then run
`flutter clean` and `flutter pub get` once in each existing local checkout to
rebuild its ignored generated files.
